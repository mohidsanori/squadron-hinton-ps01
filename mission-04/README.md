AURA's conversational policy is still an unaligned token predictor: under stress it flatters, refuses or pads its answers. This mission builds the alignment stack from first principles in PyTorch and audits what it costs:

- **DPO** — loss, log-prob extraction and gradient-flow tests, without TRL.
- **Implicit rewards** — the DPO policy as its own reward model; pairwise accuracy and Bradley-Terry calibration.
- **Verbosity** — length-bias diagnostics, reference-free SimPO, and the memory cost of the reference model.
- **Steering** — honesty vectors added to the residual stream at inference time, with an alignment-tax audit.

```bash
python 02_Implicit_Reward_Evaluator.py      # ~20 s, writes 02_bt_calibration.png

python 04_Activation_Steering_and_Audit.py  # ~75 s on an M2; downloads Qwen2.5-0.5B-Instruct (~1 GB) on first run
```

Or open `ps04_solution.ipynb` and run all cells (about 3 min). Part 4 loads the model in fp16 with batches of 4, so it fits an 8 GB laptop. Close heavy apps first anyway. `--full-sweep` tests 11 values of α instead of 5.

Parts 1–3 need no download. They train a 2-layer transformer (~113k parameters) on 2,000 synthetic *plasma-console* preference pairs. Each pair has 5 votes from simulated Bradley-Terry annotators, who give padded answers a +0.6 utility bonus: a deliberate verbosity bias for Part 3 to detect.

## What each script checks

| Script | Checks (all pass) |
|---|---|
| 01 | `get_batch_logps` equals an explicit loop exactly and does not change with padding; loss = log 2 when policy = ref; `logsigmoid` stays finite where `-log(sigmoid)` gives inf/NaN; autograd equals the closed-form gradient (1.9e-9); after 5 optimiser steps π_ref is bit-identical and has no `.grad`; held-out loss 0.693 → 0.261 |
| 02 | implicit rewards, pairwise accuracy by pair type, reliability table, ECE, temperature fit |
| 03 | SimPO loss = log(1+e^γ) at equal log-probs; length invariance of the averaged reward; lr sweep of DPO vs SimPO; memory benchmark |
| 04 | α = 0 is an exact no-op; the hook changes the forward pass; removing it restores the model exactly; cross-validated layer scan |

## Key results

**DPO and implicit rewards** (β = 0.1, lr 3e-4, 300 steps): validation pairwise accuracy is **91.5%**, against a label-noise ceiling of 93.3% (in 6.7% of pairs the 3:2 majority picked the worse response). Accuracy is 100% on sycophantic pairs, 95% on wrong-action pairs and 77.5% on verbosity pairs. The raw reward is over-confident: the fitted temperature is s = 0.68, and it lowers the NLL from 0.459 to 0.436.

**Length bias** (validation, `probe` = share of 200 held-out same-answer pairs where the reward prefers the padded version):

| method | lr | val acc | r_len (verbosity pairs) | probe | greedy output correct |
|---|---:|---:|---:|---:|---:|
| DPO | 1e-4 | 87.7% | +0.36 | 79.5% | 3.3% |
| SimPO | 1e-4 | 80.5% | −0.47 | 28.0% | 83.3% |
| DPO | 3e-4 | 91.5% | +0.60 | 91.0% | 43.3% |
| SimPO | 3e-4 | 93.0% | +0.69 | 95.5% | 26.7% |
| SFT start | — | — | — | 54.5% | 100% |

At equal training strength, SimPO's length-normalised reward stays close to length-neutral while DPO's summed reward prefers padding. Trained harder, both absorb the annotators' bias, because it is in the labels (padding chosen in 76% of verbosity pairs). SimPO removes the mechanism by which DPO rewards length on its own. It cannot fix biased data.

**Memory** (41.7M-parameter decoder, fp32, AdamW, Apple M2 / MPS):

| | DPO | SimPO | reduction |
|---|---:|---:|---:|
| resident weights | 319 MB | 160 MB | **50.0%** |
| training-step peak, 1 × 64 tokens | 847 MB | 688 MB | 18.9% |
| training-step peak, 8 × 256 tokens | 2,478 MB | 2,318 MB | 6.4% |

**Steering audit** (Qwen2.5-0.5B-Instruct, layer 8, ‖v‖ = 15.5% of the residual norm; full table in [`04_alignment_tax_report.md`](04_alignment_tax_report.md)):

| α | false claims rejected | true claims confirmed | balanced | math retained |
|---:|---:|---:|---:|---:|
| −2 | 0.0% | 100% | 50.0% | 100% |
| −1 | 10.0% | 95% | 52.5% | 100% |
| 0 | 36.7% | 85% | 60.8% | 100% |
| +1 | 66.7% | 35% | 50.8% | 94.7% |
| +2 | 90.0% | 15% | 52.5% | 92.1% |

Positive α raises truthfulness, but mostly by shifting the model toward disagreeing with the user: true-claim confirmation collapses and balanced accuracy never beats the unsteered model. Layers 12, 16 and 20 behaved the same way. **Operating bounds: α ∈ [−2, 0]; recommended α = 0. Clamp the dial to α ≥ 0**, because negative α makes the model fully sycophantic.

## Notes on the briefing

- The briefing writes γ inside r_SimPO(x, y). Subtracted from each response's reward, it would cancel in the difference. Here, as in the SimPO paper, γ is subtracted once from the margin.
- "≈ 50% VRAM reduction" holds for resident weights. For a full training step the saving is smaller (19% → 6% as the batch grows), because gradients, optimiser state and activations are paid by both methods. DPO can recover most of the gap by precomputing reference log-probs.
- The ideal submission path is `docs/weeks/week-04/problem_set/`. Following missions 01–03, this repo uses `mission-04/`.
- The notebook runs the memory benchmark for the small batch shape only, to keep an 8 GB laptop responsive. The script runs both shapes.
